Start here: what Big-O measures

We don't time algorithms in seconds, because seconds depend on the machine. We count basic steps (a comparison, an addition, reading one cell of memory) as a function of the input size n, and we only care about the shape of that function when n gets large. Space complexity asks the same question about memory: how much extra memory does the algorithm need as n grows?

n =1,000

Bars use a log scale: each grid step is 1,000× more work. Times assume a machine doing 10⁹ simple steps per second.

  • Count steps, then keep the biggest term

    3n + 5 → O(n). n² + 100n → O(n²). At n = 10⁶ the 100n part is 10⁸ next to 10¹², so it is noise.

  • Code in sequence adds, code inside loops multiplies

    Two loops one after another: n + n = O(n). A loop inside a loop: n × n = O(n²).

  • Halving gives log n

    log₂ n answers "how many times can I halve n before I reach 1?" For a million that's about 20. Doubling n adds just one more halving.

  • 1 + 2 + … + n ≈ n²/2

    "n work, then n−1, then n−2…" is quadratic even without a full n × n loop. This explains bubble, selection and insertion sort.

  • Space counts extra memory, including the call stack

    Recursion that goes d levels deep holds d frames in memory: O(d) space even with no arrays.

  • Best, average, worst

    Big-O usually means the worst case. Quicksort is O(n log n) on average but O(n²) with bad pivots; the cards list all three when they differ.
